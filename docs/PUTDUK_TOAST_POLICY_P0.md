# 퍼뜩 P0 토스트 정책 2차 분류

기준: `docs/PUTDUK_MASTER_FINAL_ARCHITECTURE.md`의 P0 토스트 정책.

## 회원 화면 유지

다음은 토스트 유지 대상이다.

- 실제 업무 제출 서버 접수 완료
- 입금 신청 서버 접수 완료
- 출금 신청 서버 접수 완료
- 다른 화면에 있을 때 새 업무 배정
- 중요한 검수·알림의 실시간 도착
- 분류되지 않은 서버 `error`/`warning` — 중요한 오류를 숨기지 않기 위한 안전 기본값

대표 문구:

- `근무 제출이 완료됐어요`
- `입금 신청을 접수했어요`
- `출금 신청을 접수했어요`
- `새 근무가 배정됐어요`
- `새 안내가 도착했어요`

## 회원 화면 인라인 전환

`dist/assets/app.js`와 `dist/assets/phase4-finance-wiring.js`의 잔여 호출을 전수 확인해 다음 계열을 인라인 피드백으로 전환한다.

- 인증·가입 폼: 비밀번호 불일치, 이메일, 생년월일, 약관·개인정보 동의, 로그인·가입 오류, 인증·재설정 메일 안내
- 입금 폼: 증빙 파일 형식·용량, 금액 재확인, 보안 PIN, 계좌·USDT 안내 잠금/해제
- 출금·본인확인 폼: 로그인 필요, 본인확인 파일 검증 및 접수 안내
- 업무 진행: 상품 입력 검증, 5건 대조 미완료, 전표 선택 오류, 제출 대기 진행 상태
- 일반 상태: 중간 저장, 첫 업무 준비, 앱 설치/PWA 안내, 알림 읽음 실패, 기능 준비 안내
- 화면 전환 직후의 일반 안내는 토스트 대신 현재 폼·모달·페이지 안에서 표시

## 회원 화면 제거

다음은 사용자 행동 결과를 중복 안내하거나 정책과 충돌하므로 표시하지 않는다.

- `배정된 라인을 라인 찾기에서 확인해요.` — 이미 해당 화면으로 이동함
- `등급과 라인이 내려가는 출금이에요.` 및 등급 강등 계열 — 원금 출금 패널티 금지 정책과 충돌

## 운영자 화면

운영자 화면은 이 가드를 적용하지 않는다. 저장·승인·반려·공개·차단·잔액조정 등 실제 운영 변경의 성공/실패 피드백은 유지한다.

## 구현 안전장치

- `#toastStack`만 관찰한다.
- 회원 모드에서만 동작한다.
- 알려진 저가치 안내는 인라인 전환한다.
- 알려진 정책 위반 문구는 제거한다.
- 분류되지 않은 `error`/`warning`은 중요한 서버 오류를 숨기지 않기 위해 유지한다.
- 한 번에 여러 토스트를 새로 만드는 엔진은 추가하지 않는다.
