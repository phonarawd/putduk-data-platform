# PUTDUK UI/UX FINAL 2026 — Legal Release Checklist

이 문서는 법률 자문 자체가 아니라, production 공개 전에 실제 사업정보·처리현황·동의증적과 화면 문구가 서로 일치하는지 확인하기 위한 출시 게이트다.

## 1. 사업자정보 — 실제 값 필수

다음 값은 추측하거나 예시값으로 공개하지 않는다.

- 상호/법인명
- 대표자
- 사업자등록번호
- 통신판매업 신고번호(해당 시)
- 사업장 주소
- 고객지원 이메일/전화번호
- 개인정보 보호책임자 성명·직책·연락처

현재 repository에서 확인되지 않은 값은 production 법률페이지 공개 전 실제 등록정보로 채운다.

## 2. 약관 동의 증적 버전

- 화면에 노출하는 이용약관 버전과 signup metadata의 `terms_version`이 정확히 일치해야 한다.
- 화면에 노출하는 개인정보 동의/처리 안내 버전과 signup metadata의 `privacy_version`이 정확히 일치해야 한다.
- 현재 FINAL 법률문구 버전은 `2026.09.19`다.
- 현재 기존 `app.js` 가입 metadata는 `terms_version: 2026-09-16`, `privacy_version: 2026-09-16`으로 확인되므로 이 불일치가 해소되기 전에는 merge 금지.
- 선택 광고성 수신동의는 `marketing_opt_in`으로 실제 signup metadata에 저장되는 것을 확인했다.
- 가능하면 광고성 수신동의의 버전·동의시각·철회시각을 감사 가능한 형태로 저장하는 별도 설계를 검토한다.

## 3. 이용약관 실제 서비스 일치

다음을 실서비스 동작과 대조한다.

- 업무 매칭 조건
- 업무 시작 금액의 실제 의미
- 업무 제출/검수/재확인/반려 상태
- 예상 수당과 확정 수당의 구분
- 지갑의 지원금/업무 잔액/출금 가능 금액 정의
- 입금 요청과 실제 잔액 반영 시점
- 출금 신청과 지급 완료 시점
- 등급·혜택 변경 조건
- 추천 보상 확정 조건
- 회원 이용제한·차단 절차

화면 문구보다 서버 동작이 우선이며, 서로 다르면 문구 또는 동작을 출시 전에 맞춘다.

## 4. 고용·업무 관계 표현

- `사원증`, `근무`, `출근` 같은 UI 명칭만으로 고용관계가 성립한다고 오해시키지 않는다.
- 실제 업무 제공 관계가 근로기준법상 근로자성 또는 다른 계약관계에 해당하는지는 계약과 실질을 별도로 검토한다.
- `수당`, `업무`, `업무 시작 금액`의 세무·노무·계약상 성격을 실제 운영모델과 맞춰 검토한다.

## 5. 개인정보 수집 최소화

회원가입에서 실제 처리하는 항목을 대조한다.

- 이름
- 생년월일
- 이메일
- 휴대폰 번호
- 추천인 코드(선택)
- 로그인/보안 기록
- 업무·정산 기록

화면 또는 DB가 사용하지 않는 개인정보는 관행적으로 추가 수집하지 않는다.

## 6. 본인확인/KYC

- 실제 KYC 법적 근거와 목적을 확인한다.
- 신분증 앞/뒤, 셀카 중 실제 필요한 자료만 받는다.
- 주민등록번호 등 고유식별정보는 법적 처리 근거 없이 수집하지 않는다.
- 별도 법적 근거가 없는 경우 불필요한 번호 마스킹 안내를 UI에 표시한다.
- KYC 원본 파일의 storage path, 접근권한, signed URL 유효시간, 삭제/보유정책을 실제 구현과 대조한다.
- PDF/이미지 허용범위가 frontend와 backend에서 일치하는지 확인한다.

## 7. 개인정보 처리방침 공개 항목

실제 운영 사실을 확인한 후 다음을 공개한다.

- 개인정보 처리 목적
- 처리 항목
- 보유 및 이용기간
- 파기 절차/방법
- 제3자 제공 현황(해당 시)
- 처리위탁 현황
- 국외 이전 현황(해당 시)
- 정보주체 권리행사 방법
- 개인정보 보호책임자/담당부서
- 안전성 확보조치
- 쿠키/브라우저 저장기술 안내
- 처리방침 변경 이력

## 8. 처리위탁·국외 이전

실제 계약/구성을 확인하기 전 회사명을 임의로 법률페이지에 기재하지 않는다.

확인 대상 예시:

- 데이터베이스/인증/스토리지 제공자
- CDN/호스팅 제공자
- 고객상담 도구 제공자
- 이메일/SMS 발송 제공자
- 분석/로그 제공자

각 서비스별 실제 법인, 처리 국가, 이전 항목, 이전 목적, 이전 시점/방법, 보유기간, 계약상 보호조치를 확인한 뒤 공개한다.

## 9. 보존기간과 실제 DB lifecycle

법률페이지의 보존기간 문구와 실제 삭제/보관 로직을 대조한다.

전자상거래법 적용 대상이라면 적용 범위에서 다음 법정 보존기간을 확인한다.

- 표시·광고 기록: 6개월
- 계약 또는 청약철회 기록: 5년
- 대금결제 및 재화 등의 공급 기록: 5년
- 소비자 불만 또는 분쟁처리 기록: 3년

PUTDUK 각 기록이 해당 범주에 실제로 해당하는지는 사업모델 기준으로 별도 확인한다.

## 10. 광고성 정보 수신동의

- 광고성 정보 수신은 선택 동의로 분리한다.
- 동의하지 않아도 기본 서비스 이용을 막지 않는다.
- 서비스 필수 알림과 광고성 알림을 구분한다.
- 수신 철회 경로를 제공한다.
- 별도 야간 동의가 없는 경우 21:00~08:00 광고성 발송 정책을 확인한다.
- 실제 발송 시스템이 동의/철회를 준수하는지 E2E 확인한다.

## 11. 금융·정산 표현

- 입금 요청 ≠ 잔액 반영 완료
- 출금 신청 ≠ 지급 완료
- 제출 완료 ≠ 검수 완료
- 예상 수당 ≠ 확정 수당
- 검수 승인 ≠ 지갑 반영 완료(실제 ledger 반영 전)

UI에 위 상태가 섞이면 merge 금지.

## 12. 외부 브랜드/협력사 표시

- 외부 브랜드 로고/이름을 표시할 법적·계약상 권한을 확인한다.
- 별도 근거 없이 `공식 협력`, `인증`, `보증` 같은 표현을 사용하지 않는다.
- 외부 플랫폼이 PUTDUK의 수익 또는 서비스 전체를 보증하는 것으로 오해시키지 않는다.

## 13. 최종 출시 게이트

아래가 모두 확인되기 전 PR을 Ready/Merge하지 않는다.

- 실제 사업자정보 입력
- 개인정보 보호책임자 정보 입력
- 이용약관/개인정보 버전과 signup metadata 일치
- 실제 처리위탁·국외이전 내역 반영
- KYC 처리 근거·보유정책 확인
- 광고성 수신동의 저장/철회 흐름 확인
- 업무/정산/입출금 문구와 서버 상태 일치
- 법률문구 한국어 Copy QA
- 모바일/데스크톱 법률페이지 visual QA
- `pnpm quality:local` exact branch HEAD PASS
- 최종 전문 법률 검토

이 체크리스트를 통과하지 않은 법률문구를 `완벽한 법적 준수`라고 표현하지 않는다.
