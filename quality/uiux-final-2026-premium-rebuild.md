# PUTDUK UI/UX FINAL 2026 — Premium Rebuild Standard

## 결정

기존 UI를 시각적으로 보존하는 것을 목표로 하지 않는다.

보존해야 하는 것은 다음이다.

- 실제 서버 데이터
- 인증·권한 계약
- 업무 배정·제출·검수 상태
- 금액 계산과 지갑 원장 값
- 입금·출금·본인확인 보안 흐름
- 기존 data-action / data-nav 등 동작 연결
- PHASE 5 보안 계약

기존 화면의 레이아웃, 카드 구조, 문구, 장식, 정보 배치는 더 나은 UX를 위해 교체할 수 있다.

## 경험 목표

회원이 다음 흐름을 끊기지 않은 하나의 실제 업무 경험으로 느껴야 한다.

1. 업무를 찾는다.
2. 업무 오더를 확인한다.
3. 업무 시작 금액·예상 수당·예상 소요를 확인한다.
4. 실제 배정 항목을 한 건씩 처리한다.
5. 완료한 내용을 제출한다.
6. 운영자 검수를 기다린다.
7. 승인·재확인·반려 결과를 확인한다.
8. 승인된 수당이 실제 지갑 상태에 반영된 것을 확인한다.
9. 업무 완료 확인서와 업무 내역에서 기록을 다시 확인한다.

가짜 주문번호, 가짜 영수증, 가짜 잔액, 가짜 정산 완료, 임의 성공 상태를 생성하지 않는다. 확인서와 영수증처럼 보이는 UI는 실제 업무/검수/지갑 상태를 표현하는 문서형 UI여야 한다.

## 화면별 목표

### 근무 홈

- 지금 할 수 있는 일과 현재 상태가 첫 화면에 보인다.
- 내부 용어보다 `업무`, `업무 매칭`, `완료한 업무`, `현재 상태`를 사용한다.
- 장식보다 다음 행동을 우선한다.

### 업무 매칭

- 업무명, 협력사, 업무 시작 금액, 예상 수당, 예상 소요, 참여 가능 여부를 한눈에 비교한다.
- CTA는 `업무 시작` 또는 `시작 조건 확인`처럼 실제 행동을 설명한다.

### 업무 오더 확인

- 업무 시작 전 확인 단계임이 명확해야 한다.
- `오더 확인 → 업무 수행 → 운영자 검수 → 정산 완료` 진행 단계를 표시한다.
- 실제 서버/업무 값만 표시한다.

### 업무 수행

- 사용자가 실제 배정 항목을 처리하고 있다는 느낌을 줘야 한다.
- 진행 건수, 현재 항목, 해야 할 행동, 제출 조건이 명확해야 한다.
- 장식 애니메이션보다 업무 정보와 입력 정확성이 우선이다.

### 제출 / 검수 대기

- 제출 완료와 검수 완료를 혼동시키지 않는다.
- 서버에 제출 기록이 저장됐다는 사실과 현재 운영자 검수 단계임을 분리해서 보여준다.
- 승인 전 확정 수당이나 지급 완료를 단정하지 않는다.

### 검수 완료 / 정산

- 실제 승인 상태일 때만 `업무 완료 확인서`를 사용한다.
- 실제 지갑 반영 상태를 근거로 정산 완료 문구를 보여준다.
- 문서형 UI는 고급스럽되 허위 문서번호나 임의 데이터를 만들지 않는다.

### 업무 내역

- 업무명, 상태, 수당, 시간, 기록 식별 정보를 읽기 쉽게 보여준다.
- 모바일은 카드 우선, 데스크톱은 표와 카드 중 읽기 좋은 형태를 사용한다.

### 지갑

- `지원금`, `업무 잔액`, `출금 가능 금액`의 의미를 명확히 구분한다.
- 처리 중인 요청은 현재 상태만 말하고 지급을 미리 단정하지 않는다.
- 입금·출금 버튼은 결과보다 행동을 설명한다.

### 입금

- 입금 수단 → 보안 확인 → 입금 정보 → 금액/증빙 → 접수의 단계가 명확해야 한다.
- 실제 제출 전에는 성공 상태를 보여주지 않는다.

### 출금

- 출금 가능 금액과 업무 잔액을 구분한다.
- 업무 잔액 포함 출금이 등급·혜택에 미치는 영향을 신청 전에 보여준다.
- 신청과 지급 완료를 명확히 구분한다.

### 본인확인

- 기술 용어보다 `본인확인`을 사용한다.
- 필요한 파일, 허용 형식, 개인정보 보호 범위, 현재 상태를 짧고 명확하게 보여준다.

### 사원증 / 등급·혜택 / 추천 / 도움말

- 다른 서비스처럼 보이지 않도록 동일한 surface, typography, spacing을 사용한다.
- 사원증은 실제 멤버십 정보 표현에 집중한다.
- 도움말은 오래된 `라인/칸/출근` 문구를 사용하지 않는다.

### 운영자

- 운영 현황 → 회원 관리 → 업무 관리 → 업무 검수 → 입출금/본인확인 → 공지의 업무 흐름을 우선한다.
- 표는 데스크톱에서 빠른 스캔이 가능해야 한다.
- 모바일에서는 가로 폭, 버튼 터치 영역, 모달 스크롤을 우선 보완한다.
- 위험 작업은 일반 조회 작업과 시각적으로 구분한다.

## 시각 원칙

- 불필요한 glassmorphism을 사용하지 않는다.
- 큰 blur 중첩을 사용하지 않는다.
- 장식용 무한 애니메이션을 최소화한다.
- 흰색/중성 surface, 얕은 그림자, 일정한 radius와 여백을 사용한다.
- 상태색은 성공/대기/주의/오류 전달에만 사용한다.
- 한국어 본문은 15–16px 수준을 기본으로 하고 지나치게 조이지 않는다.
- 제목은 한글 기준으로 자간과 행간을 별도 조정한다.
- 모바일 주요 터치 영역은 44–48px 이상을 기본으로 한다.

## 성능 원칙

- 새 프레임워크나 대형 UI 라이브러리를 추가하지 않는다.
- 원격 폰트 의존성을 추가하지 않는다.
- 새 고해상도 배경 이미지를 남발하지 않는다.
- transform/opacity 이외의 지속적 애니메이션을 최소화한다.
- MutationObserver는 added nodes 기반으로 배치 처리한다.
- 모바일에서 blur/filter를 최소화한다.
- `prefers-reduced-motion`을 존중한다.
