## 3. package-manager-independent repository gate

Repository root에서 순서대로 실행한다.

```bash
node tooling/scripts/verify-static.mjs
node tooling/scripts/typecheck.mjs
node tooling/scripts/run-node-tests.mjs 'tests/unit/**/*.test.mjs'
node tooling/scripts/putduk-backend-guards.test.mjs
node tooling/scripts/run-node-tests.mjs 'tests/e2e/**/*.test.mjs'
node tooling/scripts/run-node-tests.mjs 'tests/a11y/**/*.test.mjs'
node tooling/scripts/security-scan.mjs
node tooling/cloudflare/domain-cutover-audit.mjs
```

판정:

- 위 명령 중 하나라도 non-zero exit이면 repository gate FAIL이다.
- `domain-cutover-audit.mjs`가 final mapping 미지정으로 `PENDING`을 출력하는 것은 현재 pre-cutover 단계에서는 허용한다.
- 실제 cutover 승인 이후에는 반드시 `node tooling/cloudflare/domain-cutover-audit.mjs --require-target`를 사용하고 PASS해야 한다.
- GitHub Actions 결과는 위 판정을 덮어쓰지 않는다.

## 4. Cloudflare recovery/origin regression gate

기존 recovery middleware는 `Response.redirect()` 결과의 headers에 직접 `Set-Cookie`를 추가했다. Fetch 구현에서 redirect response headers는 immutable이므로 해당 경로는 `TypeError`가 날 수 있다.

현재 baseline에서는 redirect response를 `new Headers()` + `new Response()`로 복제한 뒤 변경 가능한 headers에 cookie와 routing fingerprint를 넣는다.

검증 계약:

- `tests/e2e/cloudflare-origin-probe.test.mjs`
- recovery toggle: 302
- query 제거된 Location 유지
- `putduk_recovery` cookie 설정/해제 가능
- redirect path에서 `context.next()` 미호출
- ops root → `/admin/` 302 유지
- native path의 `X-Putduk-Boot=native-v41` 유지
- `Clear-Site-Data` 제거 유지
- 모든 middleware response에 `X-Putduk-Origin=putduk-data-platform-pages`
- 모든 middleware response에 `X-Putduk-Router=20260921-v020-cutover1`

2026-09-21 검증 세션에서 별도 package 없이 Node Web API로 이 회귀 테스트를 직접 실행해 4/4 PASS를 확인했다. 이 실행환경은 Node 22이므로 **공식 Node 24 release PASS로 승격하지 않는다**. 대신 수정 로직 자체와 Fetch immutable-header 재현을 확인한 compatibility smoke evidence로 기록한다.

## 5. Playwright gate

Playwright는 repository-only Node test와 별도로 기록한다.

```bash
pnpm exec playwright test tests/e2e/release-auth.spec.ts
```

또는 동일한 Node 24 / Playwright 1.63.0 환경에서 로컬 binary를 직접 실행해도 된다.

판정 원칙:

- 실제 브라우저 실행을 완료한 경우에만 PASS로 기록한다.
- package/browser/runtime이 없으면 `UNEXECUTED`다.
- fallback browser smoke 또는 contract test를 공식 Playwright PASS로 바꾸어 적지 않는다.
- `release-live.spec.ts`는 승인된 전용 test account와 환경변수가 있을 때만 실행한다.
- 관리자 live gate는 `PUTDUK_E2E_MEMBER_PUBLIC_ID`로 전용 테스트 회원의 사원번호를 명시해야 하며, 이 값이 없으면 SKIP한다.
- 회원 목록의 첫 번째 행을 임의로 열어 PII를 확인하지 않는다.

### Live E2E mutation boundary

live gate의 정확한 기준은 **Production write 0**이 아니라 **사업 상태 mutation 0**이다.

금지:

- 돈/지갑/ledger 변경
- 입출금 승인·완료·거절
- 업무 시작·제출·검수·승인·반려
- 배정 생성·변경
- 등급·지원금·추천보상 변경
- MASTER 120 공개/활성화

허용되는 정상 side effect:

- 로그인/로그아웃에 따른 Auth session 기록
- 권한 확인에 필요한 보안 기록
- `super_admin`이 지정된 전용 테스트 회원의 원문 PII를 열람할 때 생성되는 `회원 개인정보 열람` audit record

실제 PII 값 자체는 assertion, 실패 로그, screenshot 설명에 포함하지 않는다. 세부 계약은 `docs/v0.2.0-phase6-release-gates.md`를 따른다.

## 6. Production read-only gate

GitHub Actions와 별개로 Production에서 직접 확인한다.

1. migration ledger
   - 기존 11개 timestamp alias는 `name_equivalent`
   - `20260921102905_phase1_kst_day_boundary`만 의도된 신규 unapplied
   - unexpected remote drift 없음
2. Phase 1 function / trigger dependency
   - `private.prepare_putduk_task_run()`
   - `private.putduk_normalize_member_tier(text)`
   - `private.putduk_lock_stake(uuid,uuid,uuid,uuid)`
   - `public.task_runs` trigger chain
3. DB integrity
   - payout plaintext 0
   - negative balances 0
   - duplicate wallet bucket 0
   - multiple active task runs 0
   - referral/assignment invariant 0
4. MASTER 120
   - templates / versions / draft-disabled nodes / active orders / fingerprints = 120 each
   - accidentally live = 0
   - internal catalog source published = 0
5. Security exposure
   - `private` schema is not usable by `anon` / `authenticated`
   - Advisor INFO는 실제 grants와 교차 확인한다.
6. Edge metadata
   - protected functions: `verify_jwt=true`
   - `push-dispatch` only: `verify_jwt=false`
   - v0.2.0 배포 후 repository contract의 9 functions가 ACTIVE여야 한다.

원문 PII, 지급정보, 계좌/주소 값은 검증 출력에 포함하지 않는다.

### 6.1 Production Edge CORS inventory

2026-09-21 Production에는 7개 Edge Function이 ACTIVE이고 repository contract의 `member-task-detail`, `admin-work-asset` 2개는 아직 미배포다.

실배포 source를 read-only로 확인한 결과:

- `admin-master` v1은 `request.headers.get('origin') || '*'` 값을 그대로 `Access-Control-Allow-Origin`에 반환하는 구형 Origin 반사형 구현이다. repository에서는 이 구현을 제거하고 `PUTDUK_ALLOWED_ORIGINS` allow-list 계약으로 수정했다.
- `admin-control`, `admin-phase5`, `member-finance`, `member-push`, `member-experience`, `push-dispatch`는 `PUTDUK_ALLOWED_ORIGINS`를 읽는 구현이다.
- 단, 위 6개 구현도 환경변수가 없으면 `*`로 fallback한다. 따라서 source inspection만으로 Production CORS PASS를 선언하지 않는다.

브라우저에서 `https://app.hiptk.app`와 `https://example.com`을 origin으로 삼아 7개 endpoint를 read-only로 확인했으나, 실행 도구가 실제 OPTIONS response header를 노출하지 못하고 unauthenticated GET이 모두 401로 끝났다. 이 결과는 인증 게이트 존재를 보여줄 뿐 **CORS allow-list가 실제 적용됐다는 증거가 아니다**. 따라서 runtime CORS는 `UNCONFIRMED`로 기록한다.

Release 시에는 다음을 모두 만족해야 한다.

1. `PUTDUK_ALLOWED_ORIGINS`가 비어 있지 않아야 한다.
2. `*`를 포함하면 안 된다.
3. 값은 path/query/hash 없는 HTTPS origin만 허용한다.
4. final member/ops mapping에서 승인된 origin만 넣는다.
5. Supabase secret을 Edge deploy 전에 동기화한다.
6. `node tooling/supabase/verify-edge.mjs`로 9개 함수 모두에 대해:
   - ACTIVE/JWT 계약
   - unauthenticated 401/403
   - 허용 origin의 `Access-Control-Allow-Origin` 일치
   - 임의 비허용 origin 반사 금지
   를 실제 배포 endpoint에서 PASS해야 한다.

수동 보조 workflow도 `PUTDUK_ALLOWED_ORIGINS`를 preflight 필수 secret으로 요구하고, Supabase secret에 동기화한 뒤 Edge를 배포하고 CORS smoke를 실행한다. GitHub Actions 자체는 필수 경로가 아니므로 동일 절차를 로컬 CLI/MCP 배포에서도 지킨다.

## 7. Direct live smoke

Actions 대신 실제 배포 origin을 직접 확인할 수 있다.

Pre-cutover read-only smoke:

- member shell load
- member login modal open
- ops shell load
- unauthenticated admin state 표시
- operator login modal open
- recovery Pages origin 응답

이 smoke에서는 자격증명을 입력하거나 로그인 제출, 돈/업무 mutation을 수행하지 않는다.

현재 확인된 baseline에서는 member/ops shell과 login UI가 정상적으로 열리고 recovery origin도 응답한다.

Cloudflare middleware가 이후 배포되면 `X-Putduk-Origin` / `X-Putduk-Router`를 direct smoke에 포함해 custom domain이 어느 routing layer에서 응답했는지 식별한다.

## 8. 현재 release STOP 조건

GitHub Actions quota/runner failure 자체는 STOP 조건이 아니다.

현재 STOP 조건은 다음과 같다.

- final member origin 미확정
- final ops origin 미확정
- old-origin redirect/recovery 정책 미확정
- Supabase Auth Site URL / Redirect allow-list 최종값 미확정
- `PUTDUK_ALLOWED_ORIGINS` 최종값 미확정
- Production runtime CORS allow-list PASS 미확인
- Phase 1 migration 미적용
- `member-task-detail` 미배포
- `admin-work-asset` 미배포
- auth-specific Playwright runtime PASS 미확인
- dedicated live member/admin E2E 미실행

## 9. Production write 순서

Final mapping 승인 전에는 Production mutation을 하지 않는다.

승인 후 순서는 `docs/v0.2.0-production-preflight.md`를 따른다.

1. final mapping
2. migration read-only preflight
3. Phase 1 migration 적용
4. post-migration integrity / MASTER 120 재검증
5. Auth cutover
6. Edge CORS secret sync
7. 9-function Edge deploy
8. protected Edge unauth + CORS smoke
9. static/runtime domain cutover
10. Cloudflare deploy/smoke
11. live auth E2E
12. 별도 최종 지시에 의한 Draft 해제 / merge / tag / launch

Production business-state mutation은 release validation에 사용하지 않는다. 인증/보안 감사 side effect는 위 계약에 한해 허용하고 실행 증거에 구분해 기록한다.
