# v0.2.0 Domain Cutover Gate

기준일: 2026-09-22 KST  
상태: **APPROVED — KEEP EXISTING PRODUCTION DOMAINS**

v0.2.0은 새 도메인으로 전환하지 않는다. 기존 운영 도메인을 그대로 Production 최종 mapping으로 사용한다.

- member origin: `https://app.hiptk.app`
- ops origin: `https://ops.hiptk.app`
- recovery Pages origin: `https://putduk-data-platform.pages.dev`
- 기존 DNS/custom-domain 연결: 유지
- MX/SPF/DKIM/DMARC/메일 관련 DNS: 변경하지 않음

## 2. 자동 domain gate

```bash
MEMBER_URL=https://app.hiptk.app \
OPS_URL=https://ops.hiptk.app \
pnpm release:domain
```

## 4. Static Production 적용 방식

Cloudflare DNS record를 직접 변경하지 않는다.

현재 repository의 Production 정적 배포 경로는 **GitHub `main` push → Cloudflare Pages Git Integration**이다. 따라서 PR #59를 `main`에 병합하면 Pages가 최신 `dist`와 `functions/_middleware.js`를 감지하여 기존 공식 도메인에 배포한다.

배포 후 반드시 확인한다.

1. Pages project origin이 최신 HTML/assets를 반환하는지
2. `https://app.hiptk.app/`가 최신 member shell/title/assets를 반환하는지
3. `https://ops.hiptk.app/admin/`가 최신 ops shell/assets를 반환하는지
4. member/ops host routing이 서로 섞이지 않는지
5. login UI가 정상적으로 열리는지
6. 신규 Edge protected endpoint가 무인증에 401을 유지하는지

## 5. Auth / CORS 정책

이번 release는 기존 Production 도메인을 그대로 사용하므로 새 hostname을 Auth 또는 CORS에 추가하는 cutover는 없다.

승인 origin은 다음 두 개다.

- `https://app.hiptk.app`
- `https://ops.hiptk.app`

Supabase Auth Site URL / redirect allow-list는 Management API/대시보드 설정 영역이며 DB migration과 분리한다. 기존 도메인 로그인 흐름이 이미 운영 중인 상태를 유지하되, password-reset destination은 별도 runtime smoke에서 확인한다.

Edge CORS 역시 기존 Production origin을 유지한다. 새 도메인 wildcard 추가는 하지 않는다.

## 6. DNS / rollback 원칙

이번 적용에서 DNS record 자체는 변경하지 않는다.

- `app.hiptk.app` 유지
- `ops.hiptk.app` 유지
- Pages custom-domain 연결 유지
- recovery Pages origin 유지
- mail DNS 유지

정적 배포 문제가 발생하면 마지막 known-good Git commit으로 revert/forward-fix하여 Pages Git Integration으로 복구한다.

Edge rollback은 `tooling/supabase/rollback-edge.mjs`의 fail-closed 계약을 사용한다. target SHA에 없는 managed 함수 삭제가 필요한 경우 명시적 승인 없이는 write하지 않는다.

DB migration은 자동 down migration하지 않고 forward-fix 원칙을 유지한다.
