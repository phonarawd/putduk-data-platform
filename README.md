# 퍼뜩 데이터 노드 플랫폼

회원용 데이터 노드 화면과 운영자용 관리센터를 분리한 신규 프로젝트입니다. 기존 퍼뜩 레포와 기존 Supabase 프로젝트는 이 프로젝트에서 사용하지 않습니다.

## 화면

- 회원 화면: `/`
- 운영자 화면: `/admin/`

회원가입·로그인·세션 복원은 신규 Supabase 프로젝트 인증과 연결되어 있습니다. 인증 완료 뒤 프로필·지갑·작업내역·알림은 본인 계정 범위에서 읽습니다. 가입 트리거는 공개 회원번호, 비공개 프로필, 기본 지갑, 신규 회원 지원금 캠페인, 추천 관계를 준비합니다.

## 실제 업무 상태

공개 업무를 시작하면 서버가 실행번호·완료 예정 시각·연출 변형·보상을 생성합니다. 화면을 닫아도 서버 실행은 유지되며, 완료 제출 뒤 운영자 관리센터의 **업무 검수** 메뉴에서 실제 기록을 확인합니다.

운영자가 **검수 완료**를 누르면 DB 트랜잭션이 업무 상태, 작업 보상 지갑, 출금 가능 잔액, 중복 방지 원장, 회원 알림, 감사 로그를 함께 반영합니다. 회원 화면은 화면 복귀와 주기 동기화로 **검수 완료** 상태와 잔액을 다시 표시합니다. 재확인·반려도 회원 알림과 작업내역에 기록됩니다.

## 운영자 시작 순서

1. 신규 Supabase Auth 계정 생성
2. 계정 UUID를 `private.admin_roles`에 `super_admin` 또는 필요한 역할(`work_review`, `content` 등)로 등록
3. 협력 확인 자료와 로고 사용 자료를 승인하고 기업을 공개
4. 업무 카드·처리 시간·보상 범위·일일 한도 등록
5. 테스트 회원으로 업무 시작 → 제출 → 검수 완료 → 회원 화면 반영을 확인
6. 입금·출금·KYC·추천 보상 운영 API를 연결한 뒤 해당 기능을 단계적으로 활성화

## 배포

Cloudflare Pages에서 빌드 명령 없이 `dist` 디렉터리를 배포합니다. 자세한 내용은 [Cloudflare 배포 안내](docs/cloudflare-deploy.md)와 [운영 아키텍처](docs/architecture.md)를 참고하세요.

브라우저에는 publishable key만 사용하며 `service_role`/secret key는 HTML, GitHub, Cloudflare Pages에 넣지 않습니다.

## 기술 기준

Node.js 24 LTS, pnpm 12.4.2, Turborepo 기준을 [기술 기준 문서](docs/toolchain.md)에 고정했습니다.

```bash
corepack pnpm@12.4.2 install --frozen-lockfile
corepack pnpm@12.4.2 verify
```
