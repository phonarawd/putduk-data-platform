# 퍼뜩 데이터 노드 구현 기준

## 공개 상태

기업과 노드는 `자료 등록 → 운영자 검토 → 공개 승인` 단계가 끝난 뒤 회원 화면에 공개한다. 공식 협력사 배지와 로고는 `verification_status=approved`, `logo_usage_status=approved`, `published=true`일 때만 표시한다.

## 작업 실행

브라우저 타이머는 화면 연출용이며, 작업의 기준은 `task_runs.expected_completed_at`과 `task_events`이다. 화면을 떠나도 자동 처리 단계는 서버에서 이어지고, 회원 입력 단계는 `task_checkpoints`에 저장한다.

## 보상

보상은 `reward_policy_version`과 함께 작업 시작 시 고정한다. 원장에 직접 잔액을 대입하지 않고, 승인된 작업·추천·지원금마다 불변 `ledger_entries`를 만든다.

## 신뢰 화면

실제 데이터 원본이 없는 카드는 `퍼뜩 연습용 데이터`로 표시한다. 기업명과 로고만으로 실제 업무가 연결된 것처럼 표현하지 않는다.

## 인증·계정 경계

회원가입과 로그인은 신규 Supabase Auth 프로젝트에만 연결한다. 가입 시 트리거가 공개 회원번호와 비공개 프로필을 분리해 만들며, 브라우저의 `localStorage`는 사용자별 키를 사용한다. 로그아웃하면 사용자 전용 캐시와 데모 미리보기가 분리된다.

## PWA 및 작업 지속성

루트 서비스 워커가 회원·관리자 셸과 아이콘을 캐시하고, 설치 프롬프트가 지원되는 브라우저에서는 설치 버튼을 제공한다. iPhone·iPad에서는 공유 버튼의 `홈 화면에 추가` 안내 토스트를 보여준다. 작업 연출 타이머는 `expected_completed_at`을 기준으로 복원하는 방향이며, 현재 정적 화면의 브라우저 연출은 서버 원장 연결 전 미리보기다.

## 관리자 경계

관리자 URL은 화면 분리만 제공하는 프로토타입이다. 운영 공개 전에 `admin_roles`를 기준으로 서버 측 권한 확인, 감사 로그, 민감 정보 마스킹을 붙인다. 브라우저에서 잔액을 직접 변경하거나 관리자 역할을 판단하지 않는다.
