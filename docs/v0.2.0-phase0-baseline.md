## 2. 문제 기준선

| 번호 | 기준 상태 | 근거/다음 검증 |
|---:|---|---|
| 1 | 확인됨 | 회원 한도는 KST이나 업무별 일일 한도 일부가 서버 날짜 기준이며 자정 강제 갱신이 없다. |
| 2 | 확인됨 | 배포 HTML에 줄바꿈이 아닌 리터럴 `\\n`이 포함되어 있다. |
| 3 | 재현시험 필요 | 로그인 오류가 원인별로 분리되지 않는다. 알려진 테스트 계정 E2E 필요. |
| 4 | 확인됨 | 전화번호는 역할별 마스킹이며 상세 모달 스크롤 문제가 보고됐다. 권한별 표시와 실제 스크롤 E2E 필요. |
| 5 | 기능 부족 확인 | 모든 상태에서 제출 내용과 검수·정산 이력을 보는 회원 상세 화면이 불완전하다. |

| 7 | 확인됨 | 출금 안내 아이콘/이모지와 장문 안내의 시각 체계가 일관되지 않다. |
| 8 | 확인됨 | 밝은 모드 잠금 카드의 대비가 부족하고 등급·해금 용어가 불명확하다. |
| 9 | 확인됨 | 추천 보상액·조건·지급 시점이 회원 화면에 명시되지 않는다. |
| 10 | 확인됨 | 도움말 정보 구조가 저밀도 카드 중심이며 탐색 구조가 약하다. |

| 12 | 사용자 증상 확인, E2E 필요 | 코드에 로그아웃 처리는 있으나 화면 전환과 캐시 정리가 보장되지 않는다. |
| 13 | 확인됨 | 검수 화면이 저장 경로를 직접 이미지 URL로 사용하여 비공개 경로가 깨질 수 있다. |
| 14 | 확인됨 | 사원증과 등급·혜택 메뉴의 정보가 중복된다. |

## 3. 첨부 화면 기준선

Phase 0에서 다음 사용자 제공 화면을 기준 자료로 확인했다.

- FOMO/다음 구간 게이지
- 검수 대기 화면
- 도움말
- 등급·혜택 밝은 모드
- 업무 매칭
- 운영자 검수 이미지 깨짐
- 지갑 빈 화면
- 추천 프로그램
- 출금 안내 아이콘·문구

원본에는 회원/운영 정보가 포함될 수 있으므로 저장소에 재업로드하지 않는다. 이후 시각 회귀 테스트는 개인정보가 제거된 테스트 데이터로 생성한다.

## 4. v0.2.0 공개 불가 조건

다음 중 하나라도 남으면 공개하지 않는다.

- KST 자정 경계 불일치
- 기존 정상 계정 로그인 실패
- 로그아웃 후 회원 화면 또는 캐시 잔존
- 관리자 상세 하단 접근 불가
- 역할과 맞지 않는 전화번호 노출
- 회원 또는 관리자 업무 이미지 깨짐
- 업무 원장과 화면 잔액 불일치
- 120개 업무의 4개 구간 배치 미완료
- 업무 자료·공급량·검수 규칙 누락
- 협력사 계약/발주/브랜드 사용 근거 미확인
- 업무내역 상세 미작동
- 밝은 모드 핵심 텍스트 대비 미달

## 5. 변경 및 복구 원칙

1. 각 Phase는 별도 검증 가능한 변경 단위로 진행한다.
2. 운영 금액과 회원 개인정보를 테스트 데이터로 사용하지 않는다.
3. DB 변경은 롤백 가능한 마이그레이션으로 작성한다.
4. 공개 상태 전환과 금액 로직은 원자적 트랜잭션으로 처리한다.
5. 120개 업무는 자동 계약 검사와 자산 검사를 모두 통과한 뒤에만 공개한다.
6. Phase 완료 후 결과를 보고하고 다음 사용자 지시 전까지 중단한다.

## 6. 다음 단계

Phase 1은 출시 차단 오류를 다룬다.

- KST 일일 경계 단일화
- 로그인 오류 분류와 정상 계정 E2E
- 로그아웃 후 세션·캐시·화면 정리
- 운영자 회원 상세 전화번호 권한과 내부 스크롤
