## 1. 퍼뜩의 제품 정체성

### 1.1 한 문장

**공고를 찾고 지원하고 기다리는 대신, 지금 할 수 있는 실제 업무를 고르고 바로 시작하는 데이터 업무 플랫폼.**

### 1.2 회원이 30초 안에 이해해야 하는 것

첫 화면에서 사용자는 다음 네 가지를 이해해야 한다.

1. 퍼뜩은 채용 공고를 모아놓은 구직 게시판이 아니다.
2. 가입하면 체험용 지원금으로 실제 업무 흐름을 한 번 경험할 수 있다.
3. 일반 업무는 업무잔액 일부가 업무 중 잠시 잠기며, 정상 정산 후 원금은 다시 업무잔액으로 돌아온다.
4. 실제 업무를 승인받아 끝냈을 때만 수당이 별도의 출금 가능 잔액으로 들어온다.

### 1.3 공개 마케팅 톤

내부 포지셔닝은 `알바몬/알바천국/잡코리아 다음 세대` 느낌을 갖되, 공개 화면에서는 특정 경쟁 서비스를 직접 깎아내리기보다 퍼뜩의 차이를 짧고 강하게 보여준다.

권장 헤드라인:

- `공고를 찾지 마세요. 오늘 할 일을 고르세요.`
- `지원하고 기다리는 구직에서, 확인하고 바로 시작하는 업무로.`
- `AI가 일을 잘게 나누고, 퍼뜩이 지금 가능한 업무를 바로 보여줍니다.`
- `면접을 기다리는 시간 대신, 오늘 끝낼 수 있는 업무.`
- `내 잔액에 맞는 업무를 바로 확인하고, 끝내고, 정산받으세요.`

금지 카피:

- 실제로 존재하지 않는 채용/협력관계를 암시하는 표현
- 수익 보장, 확정 고수익, 원금 보장처럼 읽힐 수 있는 표현
- 입금 자체가 수익을 만든다는 표현
- 실제 데이터가 아닌 사람 수/예산/마감시간을 실시간인 것처럼 표현

## 2. 첫 진입 홈: 5초 가치제안

비로그인 첫 화면은 복잡한 대시보드보다 아래 순서를 우선한다.

```text
퍼뜩
공고를 찾지 마세요. 오늘 할 일을 고르세요.

대기업·글로벌 브랜드 업무를
작은 데이터 작업으로 나눠 바로 수행합니다.

[무료 체험 시작]
[어떻게 일하나요?]
```

그 아래 3단 설명:

```text
1. 업무 선택
지금 가능한 업무를 확인합니다.

2. 바로 수행
정해진 데이터 확인/입력 업무를 끝냅니다.

3. 검수·정산
승인되면 업무 보증금은 돌아오고 수당이 별도로 지급됩니다.
```

로그인 회원에게는 같은 영역을 개인화한다.

```text
오늘 바로 가능한 최대 업무
10,000,000원
완료 수당 +1,000,000원
[바로 시작]
```

## 3. 신규가입 온보딩 전체 루프

### 3.1 가입 직후: Welcome Scene

가입 완료 즉시 일반 대시보드로 던지지 않는다.

```text
🎉 퍼뜩 사원이 되었습니다

첫 업무는 퍼뜩이 지원합니다.
체험 지원금 10,000원이 준비됐어요.

내 돈을 쓰지 않고
퍼뜩의 업무→제출→검수→수당 흐름을 먼저 경험해 보세요.

[첫 업무 시작]
```

보조 문구:

`체험 지원금은 출금용 현금이 아니라 첫 업무 체험에만 사용됩니다.`

### 3.2 체험 전 3장 스와이프

#### 카드 1 — 퍼뜩은 무엇인가

`공고를 보고 지원하는 서비스가 아니라, 지금 처리할 수 있는 데이터 업무를 직접 고르는 플랫폼입니다.`

#### 카드 2 — 왜 업무잔액이 필요한가

`일반 업무는 한정된 업무를 맡는 동안 업무 보증금이 잠시 잠깁니다. 정상 정산되면 보증금은 전액 업무잔액으로 돌아옵니다.`

#### 카드 3 — 돈은 어디서 생기는가

`수당은 잔액을 보유해서 생기는 것이 아니라, 실제 업무를 수행하고 검수 승인을 받아야 발생합니다.`

### 3.3 첫 체험

체험 카드에는 일반 업무와 다른 색/배지/카피를 사용한다.

```text
🎁 퍼뜩 지원 체험
회원 부담 0원
지원금 사용 10,000원
완료 수당 +3,000원
예상 30초
```

### 3.4 체험 완료 직후 성취 장면

```text
첫 업무 완료 🎉

업무 제출 완료
검수 후 수당 +3,000원

이제 퍼뜩의 일반 업무 방식도 확인해 볼까요?
```

### 3.5 검수 승인 직후

```text
✅ 첫 업무 승인

출금 가능 수당 +3,000원

다음부터는 내 업무잔액에 맞는 업무를
바로 선택할 수 있어요.

[업무잔액이 뭔가요?]
[다음 업무 보기]
```

### 3.6 업무잔액 설명 장면

애니메이션은 숫자 이동만 보여준다.

```text
업무잔액 300,000원
      ↓ 업무 시작
사용가능 0원 / 업무 중 잠금 300,000원
      ↓ 정상 정산
업무잔액 300,000원 + 수당 30,000원
```

핵심 문구:

`업무잔액은 일을 사는 돈이 아닙니다. 한정된 업무를 맡는 동안 잠시 잠기는 업무 보증금 풀입니다.`

### 3.7 첫 입금 전

입금 버튼을 누르면 계좌부터 보여주지 않는다.

먼저 `왜 입금하나요?` 1장 설명을 보여준다.

```text
입금하면 무엇이 바뀌나요?

업무잔액이 커질수록
한 번에 맡을 수 있는 업무 규모가 커집니다.

예: 업무잔액 300,000원
→ 최대 300,000원 업무

업무잔액 1,000,000원
→ 최대 1,000,000원 업무

정상 정산 후 업무 보증금은 다시 돌아옵니다.
수당은 별도 출금 가능 잔액에 쌓입니다.
```

CTA:

`[내 잔액에 맞는 업무 먼저 보기]`
`[업무잔액 충전]`

### 3.8 입금 승인 직후

MAX BALANCE FIT 결과를 즉시 보여준다.

```text
🚀 새로운 업무 구간이 열렸어요

업무잔액 1,000,000원
현재 가능한 최대 업무 1,000,000원
완료 수당 +100,000원

[최대 업무 바로 보기]
```

## 4. 고액 루프: 강제가 아니라 효용으로 유지

### 4.1 핵심 루프

```text
업무잔액 확보
→ 현재 잔액에 가장 잘 맞는 최대 업무 노출
→ 업무 수행
→ 검수
→ 보증금 복귀 + 수당 지급
→ 수당 출금 또는 유지
→ 다음 업무
```

### 4.2 회원이 원금을 유지하고 싶어지는 이유

강등/출금제한 대신 다음 정보를 계속 보여준다.

```text
현재 업무잔액        10,000,000원
현재 최대 업무        10,000,000원
현재 최대 업무 수당     1,000,000원

9,000,000원 원금 출금 시
남은 업무잔액          1,000,000원
출금 후 최대 업무      1,000,000원
```

### 4.3 고액일수록 업무 경험이 더 간단해지는 설계

단순히 `돈을 많이 넣었으니 쉬운 일에 더 많이 준다`가 아니라, **파트너가 높은 단가를 지불하는 고가치/고책임 데이터 검증을 적은 인터랙션으로 처리**하게 한다.

예:

- 소액: 5~10개 항목 직접 비교/입력
- 중액: 3~5개 핵심 필드 검증
- 고액: 사전 정제된 1~3개 핵심 판단 + 높은 정확성 요구
- 초고액/배정: 전용 데이터 세트의 최종 QA 또는 승인 보조

수당은 업무 보증금 때문이 아니라 해당 업무의 실제 계약가치/난이도/SLA에 의해 정해진다는 설명을 유지한다.

## 5. FOMO/성취 피드백 원칙

퍼뜩의 FOMO는 강하게 만들 수 있지만 **실제 데이터만 사용한다.**

### 5.1 사용 가능한 실제 신호

- 해당 node의 실제 `daily_cap`
- 실제 오늘 생성된 task run 수
- 실제 남은 업무 수량
- 실제 회원 본인의 남은 일일 횟수
- 실제 검수 완료 건수
- 실제 공개된 partner/node 수
- 실제 파트너 발주예산 원장이 구축된 뒤의 검증된 잔액
- 실제 assignment의 visible_until

### 5.2 금지

- 존재하지 않는 사람을 `지금 27명이 보고 있음`으로 표시
- 랜덤으로 줄어드는 가짜 남은 자리
- 실제 근거 없는 `3분 후 마감`
- 근거 없는 `기업이 30억원 예치`
- 실제 지급예산이 아닌 회원 입금액을 기업 예산처럼 표현

### 5.3 추천 FOMO 카드

실제 데이터가 있을 때만:

```text
오늘 이 업무 남은 자리 2/12
오늘 승인 완료 7건
내 남은 업무 횟수 2회
```

회원 전용 개인 FOMO:

```text
내 업무잔액으로 지금 가능한 최고 업무
1,000,000원
오늘 남은 자리 1개
```

### 5.4 성취 애니메이션

- 업무 시작: 잠금 금액이 `업무 중`으로 이동
- 50%: 진행 링
- 제출: 체크/전송 모션
- 승인: 보증금 복귀 + 수당 분리 입금 애니메이션
- 새 최대업무 해금: 카드가 한 단계 위로 올라오는 모션
- 연속 승인: streak는 `연속 업무 승인`만 표시

랜덤 상자, 룰렛, 잭팟, 확률형 보상처럼 도박에 가까운 UI는 사용하지 않는다.

## 6. 파트너 신뢰 패널

현재 Production에는 승인·공개 등록된 브랜드가 8곳 있고 operator 공개업무는 13개다. 하지만 현재 스키마에는 파트너별 실제 예치/발주예산을 증명하는 별도 funding ledger가 없다.

따라서 현재 즉시 노출 가능한 것은:

```text
승인된 파트너 브랜드
공개 업무 수
오늘 남은 업무 자리
업무별 수당
```

### 6.1 파트너 예산을 보여주고 싶다면 먼저 만들 것

신규 private/public 분리 원장:

```text
partner_funding_pools
- id
- partner_brand_id
- currency
- funded_amount
- reserved_amount
- consumed_amount
- available_amount
- source_reference
- verified_at
- verified_by
- status
- public_display_enabled

partner_budget_allocations
- funding_pool_id
- node_id
- allocated_amount
- reserved_amount
- consumed_amount
- available_amount
```

원칙:

`public_display_enabled=true`이고 관리자 검증이 끝난 pool만 회원에게 노출한다.

### 6.2 회원 업무 카드 예시

실제 예산 원장이 있는 경우:

```text
CJ대한통운 · 배송 데이터 검수

파트너 지급예산 확보됨
이 업무 배정 예산 120,000,000원
오늘 남은 업무 7건

업무 보증금 1,000,000원
완료 수당 +100,000원
정상 정산 시 보증금 전액 복귀
```

실제 예산 원장이 없는 경우:

```text
CJ대한통운 · 배송 데이터 검수
승인된 공개 업무
오늘 남은 업무 7건
```

예산 숫자를 추정해서 쓰지 않는다.

## 7. 업무 카드에 필요한 신뢰 요소

모든 일반 업무 카드에는 다음을 한 세트로 보여준다.

```text
[브랜드 로고] 브랜드명
업무명
업무 종류
예상 시간
오늘 남은 자리

업무 보증금
완료 수당
정상 정산 시 보증금 복귀

[업무 상세]
[바로 시작]
```

상세 화면에는 추가로:

- 왜 이 업무가 필요한지
- 제출해야 할 항목
- 검수 기준
- 반려 시 무엇이 되는지
- 보증금/수당 흐름
- 파트너 예산 배정 정보가 실제 존재하면 그 정보

## 8. 120개 업무 템플릿 카탈로그

> 아래는 운영자가 실제 계약/데이터 소스가 있는 경우 node로 등록할 수 있는 템플릿이다. 특정 브랜드가 실제로 이 업무를 발주했다고 자동으로 주장하지 않는다. 브랜드/계약 연결은 운영자 검증 후에만 한다.

### A. 상품 카탈로그 QA 10종

1. 상품명 오탈자 확인
2. 옵션명 표준화
3. 색상명 매핑
4. 사이즈 표기 통일
5. 브랜드명 일치 확인
6. 카테고리 분류 확인
7. 상품 이미지-설명 일치 확인
8. 중복 상품 탐지
9. 품절 표시 확인
10. 상품 핵심속성 누락 확인

### B. 가격·프로모션 데이터 10종

11. 판매가 숫자 대조
12. 할인율 계산값 확인
13. 쿠폰 적용표시 확인
14. 무료배송 조건 확인
15. 묶음가격 구성 확인
16. 지역별 가격 필드 확인
17. 통화 단위 확인
18. 가격 업데이트 전후 대조
19. 프로모션 종료표시 확인

## 10. 업무 공급이 풍부해 보이게 만드는 올바른 방법

13개 node를 100개처럼 복제해서 같은 내용을 바꾸는 방식은 사용하지 않는다.

대신:

1. 위 120개 템플릿을 `task_template_catalog`로 관리
2. 실제 파트너/데이터 소스/예산이 확보된 템플릿만 `nodes`로 publish
3. 같은 템플릿이라도 partner/data batch가 다르면 독립 node/version으로 운영
4. 공개 목록에서 카테고리·브랜드·예상시간·보증금·수당 필터 제공
5. 오늘 가능한 것과 앞으로 열릴 업무를 구분
6. 미공개 템플릿은 회원에게 실제 업무인 것처럼 노출하지 않음

### 홈의 업무 풍부함 표현

실제 공개 데이터가 충분할 때:

```text
오늘 열린 업무 47개
8개 브랜드
6개 업무 카테고리
```

실제 공개업무가 13개면 `100+ 업무`라고 쓰지 않는다. 대신 템플릿 라이브러리가 120개인 경우 운영자 화면에서 `업무 템플릿 120개`라고 표시하고, 회원 화면에는 실제 publish된 수만 표시한다.

## 12. FAQ 최종 세트

### 퍼뜩은 어떤 플랫폼인가요?

`퍼뜩은 공고에 지원하고 채용을 기다리는 서비스가 아니라, 기업 데이터 업무를 작은 단위로 나눠 회원이 지금 가능한 업무를 직접 선택하고 수행하는 플랫폼입니다.`

### 왜 입금해야 하나요?

`일반 업무는 한정된 데이터를 맡는 동안 업무 보증금이 필요합니다. 입금한 금액은 업무잔액이 되고, 업무를 시작하면 필요한 금액만 잠시 잠깁니다. 정상 정산 후 보증금은 전액 업무잔액으로 돌아옵니다.`

### 입금하면 수익이 생기나요?

`아니요. 잔액 보유 자체로 수당이 생기지 않습니다. 실제 업무를 수행하고 검수 승인을 받은 경우에만 해당 업무의 수당이 지급됩니다.`

### 업무 보증금은 수수료인가요?

`아닙니다. 일반 업무에서는 정상 정산 후 전액 업무잔액으로 돌아옵니다.`

### 원금을 출금할 수 있나요?

`가능합니다. 원금 포함 출금을 신청하면 남은 업무잔액 기준으로 이후 가능한 업무 규모가 다시 계산됩니다.`

### 왜 업무잔액이 많으면 더 큰 업무가 보이나요?

`업무마다 맡는 동안 필요한 보증금 규모가 다르기 때문입니다. 현재 사용 가능한 업무잔액보다 크지 않은 업무 중 가장 큰 업무를 우선 추천합니다.`

### 고액 업무가 더 간단해 보이는 이유는 무엇인가요?

`고액 업무는 많은 수작업을 하는 대신 사전 정제된 데이터의 핵심 값을 최종 확인하는 형태가 많습니다. 클릭 수는 적지만 정확성과 책임 기준은 더 높을 수 있습니다.`

### 기업 예산이 확보됐다는 표시는 무엇인가요?

`파트너 funding ledger에서 실제 확인된 발주 예산만 표시합니다. 검증된 예산 정보가 없는 업무에는 금액을 표시하지 않습니다.`

### 지원금 10,000원은 출금할 수 있나요?

`아니요. 신규 가입 지원금은 첫 업무 체험용입니다. 체험 업무에서 발생한 승인 수당은 출금 가능 잔액에 반영됩니다.`

### 반려되면 보증금은 어떻게 되나요?

`일반 업무의 보증금은 정산 규칙에 따라 업무잔액으로 복귀하며, 수당은 승인된 업무에만 지급됩니다.`

## 16. 테스트 계약

### 온보딩

- 신규 가입자는 체험 지원금 10,000원을 명확히 확인
- 체험에서 회원 본인 원금 반환 카피가 나오지 않음
- 체험 승인 후 3,000원 수당이 available에 표시
- `왜 입금하나요?` 설명을 계좌정보보다 먼저 볼 수 있음

### 업무 카드

- 모든 일반 업무가 stake/stipend/return 설명을 가짐
- `requires_assign`이면 일반 회원에게 노출되지 않음
- best-fit이 첫 카드

### FOMO

- 남은 자리는 실제 cap/run 데이터와 일치
- 가짜 countdown 없음
- 가짜 viewer count 없음
- 실제 funding ledger 없이는 예치금 표시 없음

### 카탈로그

- template 120개 이상
- template 자체는 회원 공개업무로 계산하지 않음
- publish된 node만 회원 업무수에 포함
- 실제 브랜드 연결 없는 template은 브랜드 업무처럼 표시하지 않음

### 성능

- 첫 화면 LCP를 FOMO animation이 막지 않음
- 모바일 320px에서도 핵심 CTA가 첫 viewport에 존재
- reduced-motion 환경에서 모든 animation 비활성/축소
- canvas는 viewport 밖에서 정지

## 17. 완료 판정

완료 후 신규 회원은 별도 설명서를 읽지 않아도 다음을 이해해야 한다.

```text
퍼뜩 = 공고 지원 앱이 아니라 바로 수행하는 데이터 업무 플랫폼
가입 지원금 = 첫 체험용
업무잔액 = 일반 업무를 맡는 동안 잠기는 보증금 풀
수당 = 실제 업무 승인으로만 발생
입금 = 더 큰 업무를 맡을 수 있는 업무잔액 확보
원금 출금 = 가능, 단 남은 잔액만큼 업무규모 감소
파트너 예산 = 실제 검증된 funding 데이터만 표시
FOMO = 실제 남은 업무/자리/완료건만 표시
```

그리고 사용자 감정은 다음 순서가 되어야 한다.

```text
이게 뭐지?
→ 아, 공고 지원이 아니라 바로 일하는 구조구나
→ 지원금으로 먼저 해볼 수 있네
→ 돈이 왜 필요한지도 이해됐다
→ 내 잔액으로 지금 할 수 있는 일이 바로 보이네
→ 끝내면 원금은 돌아오고 수당은 따로 들어오네
→ 더 큰 업무를 하고 싶으면 업무잔액을 유지하면 되는구나
```

이 흐름을 깨는 가짜 사회적 증거, 허위 예산, 숨겨진 출금 불이익, 수익 보장 문구는 넣지 않는다.
