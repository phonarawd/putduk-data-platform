# PUTDUK UI/UX FINAL 2026 — Korean Copy & Typography Standard

## Purpose

회원 화면은 한국 사용자가 처음 봐도 바로 이해되는 친절한 해요체를 사용하고, 운영자 화면은 짧고 정확한 업무형 문구를 사용한다. 번역체, 시스템 내부 용어 노출, 띄어쓰기 흔들림, 과도하게 긴 버튼 문구를 피한다.

## Product terminology

- 사용자 메뉴 기능명: `업무 매칭`
- `라인 찾기`는 사용자 UI 기능명으로 사용하지 않는다.
- 내부 멤버십 등급의 `라인`, 물류 거점명/협력사 문맥의 `○○ 라인`, 데이터 필드·서버 계약 용어는 의미가 다르므로 무조건 치환하지 않는다.
- `본인확인`을 기본 사용자 표현으로 사용한다. 기술 설명에서만 KYC를 괄호로 병기할 수 있다.
- `출금 가능 금액`, `업무 잔액`, `지원금`, `보류 금액`처럼 사용자에게 보이는 금액 명칭은 띄어쓰기를 유지한다.

## Voice and tone

### Member UI

- 기본: 짧고 친절한 해요체.
- 한 문장에는 한 가지 행동이나 상태만 담는다.
- 성공·대기·실패를 감정적인 과장보다 실제 상태 중심으로 설명한다.
- 사용자가 직접 판매·정산·승인을 처리하는 것처럼 오해하게 만드는 표현을 쓰지 않는다.

권장 예:
- `업무가 배정됐어요. 업무 매칭에서 확인해 주세요.`
- `입금 신청을 접수했어요. 확인이 완료되면 잔액에 반영됩니다.`
- `본인확인이 필요해요. 필요한 자료를 제출해 주세요.`
- `지금 참여할 수 있는 업무가 없어요.`

피해야 할 예:
- `라인을 획득하세요!`
- `돈이 곧 들어와요!`
- `무조건 완료됩니다.`
- `판매 준비하기`처럼 사용자가 직접 판매 등록을 하는 것으로 오해할 수 있는 표현

### Admin UI

- 기본: 명사형 또는 짧은 업무형 문구.
- 상태와 행동을 명확히 분리한다.
- 위험한 작업은 결과를 먼저 설명한 뒤 확인한다.

권장 예:
- `회원 상세`
- `본인확인 검토`
- `출금 승인`
- `처리 내역`
- `차단 해제`
- `금액 확인`

## Spacing and orthography

다음 표기를 기준으로 고정한다.

| 비권장 | 권장 |
| --- | --- |
| 출금가능 | 출금 가능 |
| 휴대폰번호 | 휴대폰 번호 |
| 중복확인 | 중복 확인 |
| 확인후 | 확인 후 |
| 처리중 | 처리 중 |
| 검토중 | 검토 중 |
| 승인완료 | 승인 완료 |
| 재제출필요 | 재제출 필요 |
| 입력해주세요 | 입력해 주세요 |
| 확인해주세요 | 확인해 주세요 |
| 출금가능해요 | 출금할 수 있어요 |

`해주세요` 계열은 보조 용언 원칙에 맞춰 `해 주세요`를 기본으로 한다. 단, 기존 법률/정책 문구의 확정된 원문은 임의로 바꾸지 않는다.

## Button labels

버튼은 설명문이 아니라 행동 이름으로 쓴다.

- `업무 매칭`
- `업무 매칭 시작`
- `업무 시작`
- `시작 조건 확인`
- `입금하기`
- `출금하기`
- `내역 보기`
- `본인확인 시작`
- `확인`
- `다시 입력`
- `취소`

버튼 하나에 두 문장 이상의 설명을 넣지 않는다. 추가 설명은 버튼 위/아래의 본문에 둔다.

## Member dashboard

근무 메인은 내부 처리 절차보다 현재 가능한 행동을 먼저 보여준다.

권장 정보 순서:
1. `지금 참여할 수 있는 업무`
2. `내 조건에 맞는 업무를 확인해 보세요.`
3. `업무 매칭 시작`
4. `매칭 가능 업무 / 완료한 업무 / 오늘 남은 횟수 / 현재 상태`

피해야 할 표현:
- `작업실에 출근하고 한 칸만 확인해요.`
- `오늘 라인`
- `로그인 후 출근`

## Work matching page

업무 매칭 카드는 내부 처리 용어보다 사용자가 실제로 비교해야 할 조건을 먼저 보여준다.

카드의 정보 우선순위:
1. 협력사 / 업무명
2. 업무 시작 금액
3. 예상 수당
4. 예상 소요
5. 참여 가능 수량
6. 시작 행동

회원용 표시 문구:
- `근무 보증` → `업무 시작 금액`
- `지원금 잠금` → `업무 시작 금액`
- `수당` → `예상 수당`
- `시간` → `예상 소요`
- `남은 자리` → `참여 가능`
- `출근하기` → `업무 시작`
- 준비 조건이 충족되지 않은 경우 `입금 안내`보다 `시작 조건 확인`을 우선한다.

상단 설명 권장 문구:
`업무별 시작 금액, 예상 수당, 예상 소요를 비교해 보세요. 업무를 선택하면 실제 진행 조건을 한 번 더 확인할 수 있어요.`

주의:
- 표시 문구 변경으로 stake/reward/assignment 계산을 바꾸지 않는다.
- 실제 금융·업무 계약은 기존 서버 기준을 유지한다.
- 물류 거점명이나 등급처럼 데이터 자체가 `라인`을 의미하는 경우 임의 변경하지 않는다.
- 희소성·남은 수량 표현은 실제 근거가 있는 값만 사용한다.

## Status labels

### Identity verification

- `본인확인 전`
- `검토 중`
- `승인 완료`
- `재제출 필요`

### Deposit / withdrawal

- `접수 완료`
- `처리 중`
- `승인 완료`
- `반려`
- `출금 완료`

같은 서버 상태를 화면마다 다른 한국어로 번역하지 않는다.

## Numbers, money, dates

- 원화: `1,250,000원`
- 횟수: `3회`
- 시간: `24시간`, `10분 이내`
- 비율: `12.5%`
- 날짜: `2026. 9. 19.`을 문서형 기본값으로 사용하되, 실시간 UI에서는 현재 `ko-KR` 포맷 계약을 유지할 수 있다.
- 숫자와 `원`, `%`, `회` 사이에는 불필요한 공백을 넣지 않는다.

## Typography

- 본문 기준: 15–16px, 자간 약 `-0.01em` 수준, 행간 1.55–1.7.
- 제목: 본문보다 조금 더 좁은 자간을 사용하되 한글이 뭉칠 정도로 강하게 줄이지 않는다.
- 작은 안내 문구도 핵심 정보라면 12px 미만으로 내리지 않는다.
- `word-break: keep-all`을 기본으로 하되 긴 이메일·ID·파일명 등은 `overflow-wrap`으로 안전하게 줄바꿈한다.
- 주요 터치 대상은 모바일에서 44px 이상을 기본으로 한다.

## Mobile rules

- `업무 매칭` 필터는 작은 화면에서 가로 스크롤할 수 있다.
- 업무 카드의 금액 정보는 430px 이하에서 한 열로 쌓는다.
- 카드의 최종 행동 버튼은 작은 화면에서 전체 너비를 사용한다.
- 하단 탭과 modal이 겹치지 않게 safe-area를 반영한다.

## UI QA checklist

릴리스 전 다음을 확인한다.

1. `라인 찾기`가 사용자 기능명으로 남아 있지 않은가.
2. 내부 등급/물류 의미의 `라인`을 잘못 치환하지 않았는가.
3. 회원 화면 말투가 해요체로 일관적인가.
4. 버튼 문구가 짧고 실제 행동과 일치하는가.
5. 띄어쓰기와 상태명이 화면별로 일관적인가.
6. 금액·단위·날짜 표기가 일관적인가.
7. 320/360/390/430px에서 한글이 잘리거나 한 글자만 어색하게 떨어지지 않는가.
8. 금융/KYC 문구가 실제 서버 처리보다 먼저 성공을 단정하지 않는가.
9. 접근성 라벨도 화면 문구와 같은 용어를 쓰는가.
10. 업무 매칭 카드의 값 계산이나 서버 계약이 표시 문구 변경 때문에 달라지지 않았는가.
11. 새 문구 때문에 버튼 높이·카드 높이·모달 스크롤이 깨지지 않는가.
